# Local HTTP contract — schema v1

JSON commands and queries under `/api`, with `{ "error": "…" }` on application errors. Domain conflicts return 409, unknown games 404, and invalid browser origin/Host 403. Axum rejects malformed JSON with 4xx. Node IDs are stable UUIDs; a null point is pass; points are row-major 0–360 from the top-left. Color is `B` or `W`. Timestamps are UTC RFC3339. The backend is authoritative.

| Route | Request | Response / behavior |
| --- | --- | --- |
| GET `/state` | — | schema version, game metadata, settings, separate worker statuses, actual Auto `opponent_rank`, `opponent_komi`, data directory |
| GET `/events` | — | SSE `sync` event immediately, then invalidations for status/data changes; fetch state after every reconnect; keepalives enabled |
| PUT `/settings` | Settings object | Saves paths/budgets/classification/resignation parameters; asynchronously restarts and validates workers |
| PUT `/settings/player` | `{player_name:string}` | Saves only the trimmed name/handle (optional, at most 80 characters, no control characters), retaining all engine settings and running workers; emits a state invalidation. Settings JSON includes `player_name`, defaulting to empty for existing data. |
| POST `/engine/restart` | `{}` | Restarts both workers, revalidates profiles, recovers pending turns and missing analysis |
| POST `/games` | `{mode:"auto"|"manual",rank?,starting_rank?,color?:"B"|"W"}` | `{id}`; requires a validated rank-conditioned human model |
| GET `/games/{id}?node={node}` | Optional selected node | game + normalized node map, selected board, authoritative `previous_position` (null at root), analysis map, recalculated move reviews, `candidate_reviews` for the selected position and its parent (point, category, provisional flag, confidence visits), thinking flag, `analysis: {completed,total,queued,running}`; selection is never persisted as active head |
| GET `/games/{id}/preview.svg?head={node}&v=1` | Immutable move-node ID (required), representation version | SVG board including captures and last move; no evaluations. Private immutable browser cache, bounded server LRU, ETag and conditional 304. Use the active head from `/state`; no full game fetch is needed. |
| POST `/games/{id}/moves` | `{parent,point:number|null,review:boolean,expected_head?}` | `{node}`; Play requires matching active-head token, human turn and unfinished game; Review changes no active result; same move/parent reuses a node |
| POST `/games/{id}/variations` | `{parent,points:(number|null)[]}` (1–256 moves) | `{nodes:string[]}`; atomically validates/saves a complete review-only continuation, including on finalized games. Invalid lines save nothing; retries reuse node IDs. Active head, result and rating stay unchanged; analysis is queued asynchronously. |
| POST `/games/{id}/continue` | `{node,expected_head,resume?:boolean}` | Switches active continuation and generates opponent move if needed; resume resets pass count at that node without deleting passes |
| POST `/games/{id}/retry` | `{}` | Retries a pending opponent turn; per-game generation is deduplicated |
| POST `/games/{id}/analysis` | `{node,deep?:boolean,prepare_review?:boolean}` | Deduplicated priority request for the selected position and its parent, retaining older background work; `prepare_review:true` queues missing game positions and progressively upgrades weak estimates for either player throughout the game tree without changing confidence thresholds; successful background evaluations schedule their own follow-up work; data arrives via SSE invalidation and GET |
| POST `/games/{id}/analysis/cancel` | `{}` | Cancels queued work for game and interrupts the analyzer |
| POST `/games/{id}/resign` | `{head}` | Finalizes loss by resignation; retry returns existing immutable result |
| POST `/games/{id}/score` | `{head,dead:number[],confirm?:boolean}` | Queues deep ownership if missing, otherwise score + agreement/disagreement + suggested whole dead groups; only agreed `confirm:true` finalizes |
| GET `/games/{id}/audit` | — | New games: `before_level`, `after_level`, `opponent_level`, result, timestamp, algorithm `rank-half-step-v1`. Historic Elo records retain their previous response. Null for unfinished/imported games. |
| GET `/games/{id}/sgf` | — | `<player_name>-vs-<rank>-<YYYY-MM-DD>.sgf` attachment including variations and active-head/resume metadata; uses the current saved player name, the actual game rank and its recorded creation date. Unicode download names use `filename*` with a safe ASCII fallback. Empty/unsuitable names fall back to `player`. |
| POST `/games/import` | `{sgf:string}` | `{id}` for a review-only imported record, no progression event |

Finalization is transactionally idempotent by game ID. In-flight engine replies also carry an expected active head; stale responses cannot overwrite a changed or finalized continuation. The UI keeps its selected node and Play/Review state separately and rejects stale navigation responses. Evaluations are displayed only in Review (scoring has its separate explicit agreement flow).

Game metadata includes immutable `rank` (actual human SL profile), `half_rank` (internal difficulty phase), `komi` and `initial_stones` (`[color,point]` pairs). Regular games have 7.5 komi and no setup. Half-steps have 0.5 komi; human Black games start with White stones at 72/Q16 and 288/D4, with Black to play. Setup stones are not move nodes. Selected/previous positions and SVG previews include them; scoring, human policy and strong analysis use the same saved conditions. Manual creation always uses regular conditions at `rank`. Auto creation uses the profile's current level.

Internal audit levels are twice the rank coordinate plus the half-step flag: regular 5k = -10, harder 5k = -9, regular 4k = -8; regular 1k = -2, harder 1k = -1, regular 1d = 0. Finalization sets the next level to `opponent_level + 1` for a human win, otherwise `opponent_level - 1`, clamped to [-40,16] (20k–9d). `before_level` records the profile before finalization, which can differ from the level played in Manual mode or when games finish out of order. SQLite schema v2 replaces the live Elo profile and adds `rank_events`, retaining `rating_events` for historical audits; HTTP schema v1 is extended with the new fields.

SGF accepts 19×19 AGA games with 7.5 or 0.5 komi. Root `AW` accepts exactly two distinct White setup stones with 0.5 komi; `PL`, when present, must be `B`. Other setup/handicap forms remain unsupported. Export includes the game's komi and root setup, preserving variations without introducing artificial opening moves.

Exports put the saved name (or `Player`) in the human's `PB`/`PW`, the actual Human SL rank in the bot's `BR`/`WR`, and the recorded game start date in `DT`. Rank values use `5k`/`1d` notation and dates use `YYYY-MM-DD`, following the [SGF FF[4] game-info properties](https://www.red-bean.com/sgf/properties.html#BR). Half-step games retain their actual model rank and saved komi/setup. Names are SGF-escaped independently of filename sanitization; the filename replaces separators/punctuation with hyphens while preserving letters, digits, underscores and Unicode letters.

Both human and opponent moves enqueue asynchronous analysis of their pre-move and resulting positions. Review preparation covers missing results for both colors and existing branches. Cached results persist in SQLite and are reused after navigation and restart; progress in the review UI counts both players on the active played continuation. Quick analysis defaults to 64 visits, deep to 256, based on the installed-engine probe. Weak review comparisons are refined in bounded steps up to the greater of 4096 visits and the configured deep budget. A review confidence string ending in `search limit reached` denotes uncertainty at that limit rather than queued work; the UI distinguishes this from Pending. Model revisions are recorded with path, byte length and modification time; configurations use SHA-256. Evaluations retain the engine version/backend output, exact query, enforced worker overrides, visits, timestamp, candidate variations, ownership and classification version at inference. Display classifications are recalculated from raw stored evaluations using the current calibration version. The model identity is a local file identity rather than a content digest; retaining the model files is recommended for reproducibility.

Candidate ratings are derived from cached raw estimates using the same rank-adjusted loss thresholds as played moves. `provisional:true` means the candidate has insufficient confidence for a formal played-move classification; its estimated category is useful for coloring/ranking alternatives without weakening the confidence gate. Actual move reviews and their completion counts remain unchanged. The frontend prefers an existing child’s completed category over its provisional candidate estimate.
